# 06. 로드맵 · 테스트

## 1. 마일스톤

각 단계는 "동작하는 세로 조각"으로 끝난다. 앞 단계의 API 계약을 깨지 않는다.

### M0 — 스파이크 / 측정 (2~3일)

- [ ] `faster-whisper` + Silero VAD로 15초 세그먼트 추론 벤치마크 (GPU 1장)
- [ ] RTF, partial 지연, VRAM, 동시 세그먼트 수 측정
- [ ] 배치 1시간 파일 처리 시간 측정
- [ ] 결과로 `MAX_ACTIVE_STREAMS`, 배치 크기, partial 주기 기본값 확정
- [ ] `run.sh`(자체 호스팅)와 `notebooks/colab_stt_api.ipynb`(Colab Pro)로 같은 코드 실행 확인
- **산출물**: `bench/RESULTS.md` (수치), 런처 2종 동작 확인, 모델/파라미터 결정

> 두 실행 환경의 차이와 제약은 [08-runtime-environments.md](08-runtime-environments.md)에 정리되어 있다.

> 이 단계 없이 동시성 수치를 약속하지 않는다. 모든 SLA는 실측으로 보정.

### M1 — Batch 최소 동작 (1주)

- [ ] 업로드(multipart) → 잡 생성 → 단일 워커 처리 → 폴링 → JSON/TXT/SRT 조회
- [ ] ffmpeg 전처리, VAD 분할, 순차 처리(병렬 없이)
- [ ] 상태 머신 + 조건부 전이, 오류 코드
- **완료 기준**: 10분 파일이 정확한 타임스탬프로 전사되고, 실패 상태가 남지 않음

### M2 — Batch 병렬화 + 결과 안정화 (1주)

- [ ] 청크 병렬 처리(워커 프로세스 N개), 진행률
- [ ] 청크 병합/오프셋/중복 제거, SRT/VTT 변환
- [ ] 취소, 재시도, `Idempotency-Key`, 웹훅
- [ ] PostgreSQL/Redis/MinIO 연동
- **완료 기준**: 1시간 파일 처리, 취소/워커 강제 종료 후 상태 일관성

### M3 — Streaming (1.5~2주)

- [ ] `WSS /v1/stream`: ready/partial/final/done/error
- [ ] VAD 세그멘테이션, pre-roll, partial 주기, flush/end/ping
- [ ] 세션 카운터/쿼터, 링 버퍼 백프레셔, 타임아웃
- [ ] 세션 결과 조회, 이벤트 리플레이
- **완료 기준**: 5분 발화의 final이 batch 결과와 CER 차이 5%p 이내, p95 지연 목표 충족

### M4 — 동시성/공정성 (1주)

- [ ] 우선순위 큐(streaming > batch), 가중 공정 분배
- [ ] 마이크로배칭 스케줄러(배치 크기/대기 시간)
- [ ] 테넌트별 동시성/레이트 리밋, `429`/`503` + `Retry-After`
- [ ] Hybrid: batch 잡 SSE 구독(리플레이 + live)
- [ ] 부하 테스트: 스트리밍 100 + 배치 50
- **완료 기준**: 부하 중 스트리밍 p95 지연 저하 ≤ 20%, 오류율 < 0.1%

### M5 — 운영 준비 (1주)

- [ ] 메트릭/트레이스/알림, `/readyz`, 그레이스풀 셧다운
- [ ] K8s 매니페스트, HPA/KEDA, GPU 노드 풀
- [ ] 보안 점검(키 회전, presigned, 웹훅 서명, 로그 PII)
- [ ] 골든셋 회귀 파이프라인
- **완료 기준**: 카오스 시나리오(워커 kill, Redis 재시작) 통과, 런북 작성

### v2 후보

화자 분리 · 단어 타임스탬프 고도화 · 스트리밍 resume · 다국어 자동 전환 · 커스텀 어휘/prompt · 온프렘 패키지 · 실시간 번역

## 3. 테스트 전략

### 단위

- VAD 상태 전이(무음→발화→무음, 짧은 발화, 잡음)
- 세그멘터: pre-roll, 최대 길이 강제 분할, 경계 오프셋
- 병합: 청크 오프셋, 겹침 중복 제거, 정렬/불변식
- 상태 머신: 허용/금지 전이, 조건부 UPDATE 경합(동시 2개 전이 시 1개만 성공)
- partial revision 규칙(낮은 revision 무시)

### 통합

- API + Redis + Worker + Postgres를 compose로 띄우고 **작은 모델(tiny)** 로 end-to-end
- Batch: 업로드→완료→SRT 파싱; 취소; 워커 kill 후 재큐; 멱등 재제출
- Streaming: 고정 오디오를 실시간 속도로 주입(fake clock), final 순서/문자열 검증
- Hybrid: 제출 직후 SSE 연결 → 리플레이+live, 늦은 구독자도 전체 수신

### 부하/내구

- WS 100 세션 + batch 50 잡 동시 30분(soak). 메트릭: p95 지연, 오류율, 메모리 증가
- 느린 소비자(수신 지연 주입)에서 링 버퍼 drop과 `slow_consumer` 동작
- Redis/워커 장애 주입, 재시작 후 상태 복구

### 품질 회귀

- 골든셋 CER/WER, 경계 오차, partial 변동 횟수. CI에서 tiny 모델로 스모크, 야간에 실제 모델.

## 4. 리스크와 대응

| 리스크 | 영향 | 대응 |
|---|---|---|
| 스트리밍 partial 재디코딩으로 GPU 비용 폭증 | 비용/지연 | 세그먼트 상한 15 s, partial 300~500 ms, 문맥 prompt 최소화, `fast` 티어 |
| 배치 폭주가 스트리밍 지연 악화 | SLA 위반 | 우선순위/가중 공정 큐, 테넌트 쿼터, 배치 야간 스케줄 |
| Whisper 환각(무음/잡음) | 품질 | VAD 게이트, no_speech 임계, 반복 필터, 골든셋 회귀 |
| 세그먼트 경계 문맥 손실 | 품질 | 오버랩 디코드 + 단어 타임스탬프 기반 중복 제거 |
| WS 연결이 많은 API 레플리카에 분산 | fan-out 복잡도 | Redis Stream 기반, 세션 소유권 명시, 초기 단일 레플리카 |
| Redis 휘발 | 상태 불일치 | PG를 source of truth, 복구 스캔, AOF |
| GPU 콜드스타트 | 초기 지연/타임아웃 | 최소 워커 유지, warmup, readiness |
| 긴 파일 메모리 사용 | OOM | ffmpeg 스트리밍 디코드, 청크 단위 처리, 상한 고정 |
