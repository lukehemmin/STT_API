# 07. 확정이 필요한 결정

아래 항목은 계획의 기본값을 바꿀 수 있다. **권장안**으로 진행하되, 답이 오면 문서를 갱신한다.

## D1. STT 엔진: 자체 호스팅 vs 클라우드

| 선택지 | 장점 | 단점 |
|---|---|---|
| **faster-whisper 자체 호스팅 (권장)** | 데이터 통제, 고정 비용, 스트리밍 제어 자유 | GPU 운영, 품질 튜닝 부담 |
| 클라우드 STT API 래핑 | 빠른 시작, 관리형 품질 | 스트리밍/배치 계약 불일치, 비용 증가, 벤더 종속 |
| 하이브리드 | 기본 자체, 피크/특수 언어만 클라우드 | 어댑터 2개 유지 |

→ **Transcriber 인터페이스로 추상화**해두고 M1은 자체 호스팅으로 시작. 클라우드 어댑터는 필요 시 추가.

**필요 정보**: GPU 예산, 데이터 반출 가능 여부, 예상 월 오디오 시간.

## D2. 지원 언어/도메인

- 초기: 한국어 + 영어 (코드 스위칭 포함) 가정.
- **필요 정보**: 의료/법률/금융 등 도메인 용어 사전 필요 여부, 방언, 다국어 회의 비중.

## D3. 스트리밍 입력 규격

- 기본: `pcm_s16le` 16 kHz mono. 브라우저는 WebAudio로 리샘플 후 전송.
- 대안: 서버에서 임의 포맷 리샘플(구현 복잡, 지연 증가).
- **필요 정보**: 클라이언트가 PCM을 만들 수 있는가, Opus/WebM을 그대로 보내야 하는가.

## D4. 최대치/쿼터

| 항목 | 제안 |
|---|---|
| 파일 크기 | 2 GB |
| 배치 길이 | 4시간 |
| 스트리밍 세션 | 2시간 |
| 동시 스트림(키당) | 5 |
| 동시 배치(키당) | 20 |

**필요 정보**: 실제 최대 파일 크기, 최대 동시 사용자, SLA 등급.

## D5. 결과 전달 기본값

- Batch: 폴링 + 웹훅 + SSE 모두 제공(권장). 고객이 웹훅을 받을 수 없는 환경이면 폴링만.
- **필요 정보**: 콜백 수신 가능한 엔드포인트가 있는가, 결과를 얼마나 보관해야 하는가.

## D6. 인증/테넌시

- 기본: 정적 API 키 + 테넌트.
- 대안: OAuth2/JWT, 고객별 프로젝트/키 계층.
- **필요 정보**: B2B 다테넌트인가, 사용자 단위 과금인가.

## D7. 부가 기능 우선순위

| 기능 | 시점 |
|---|---|
| 단어 타임스탬프 | M1 (옵션) |
| 화자 분리 | v2 |
| 스트리밍 resume | v2 |
| 실시간 번역 | 범위 밖 |
| 커스텀 어휘/prompt | v2 |

**필요 정보**: 자막(SRT/VTT)이 1차 목적인가, 화자 분리가 필수인가.

## D8. 배포/실행 환경

- 기본: **두 경로를 모두 지원**한다.
  - 자체 호스팅: GPU 서버 + `./run.sh` (운영 기준)
  - Colab(Pro): `notebooks/colab_stt_api.ipynb` (데모/PoC/모델 검증, 세션 종료 시 중단)
- 두 경로는 같은 `app/`과 환경 변수를 쓴다. 차이는 런처와 외부 접속 방식(고정 주소 vs cloudflared 임시 URL)뿐이다. 상세: [08-runtime-environments.md](08-runtime-environments.md)
- **필요 정보**: 자체 호스팅 GPU 종류/수량, 클라우드/온프렘 여부, 관리형 Postgres/Redis 사용 가능 여부, 리전/데이터 상주 요구, Colab을 데모 외에 쓸지 여부.
